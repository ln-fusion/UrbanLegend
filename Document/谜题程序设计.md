# 网站检索与聊天叙事：谜题程序设计

版本：0.3｜2026-10-19｜首段原型已实现。UI 已改为编辑器保存的场景及 Prefab；实际入口、编辑方式、素材路径与检查方式见《程序实现与素材清单.md》，本文保留设计依据。

## 已确认的方向

主要乐趣在搜索信息。通过帖子、报道和图片寻找 ID、密码、检索词或档案编号，进入新的页面与记录。多个都市传说在同一次调查中交织。朋友通过仿微信聊天传来现场文字和图片，通信中断承担遇险叙事。

首版只制作游戏内网页和聊天界面、必要的图片及少量声音。不制作玩家可走动的现场、角色动画、调查板、证据卡收集、片段标记或自动验证推理系统。玩家自己理解材料，程序只验证明确的输入与操作。

## 核心循环

搜索关键词 → 阅读帖子／报道／图片 → 找到账号或密码等信息 → 登录系统或输入检索条件 → 获取新记录 → 与朋友通信 → 新消息引出下一轮搜索。

账号、密码、检索编号来自不同材料，可以交换查找顺序。登录成功仅表示取得访问权限；其内容可以立即打开另一条调查，不安排每个网站各自结案。

## 第一段谜题示例（原创，待定）

具体正文、角色和输入以[第一段调查内容稿](第一段调查内容稿.md)为准；主要角色为女性，不改变系统范围。

朋友发来一个旧资料检索系统的地址，说：“入口密码我找到了，是旧站共用的阅览口令；账号得用那个人当年的用户 ID。”这里明确是旧系统的共用口令，避免变成毫无来由地拿到某人的私人密码。

玩家搜索朋友提到的旧帖标题，发现论坛昵称与登录 ID 不同。在作者个人页的旧截图或报道附图中找到真实的用户 ID，配合朋友提供的口令登录。ID 要有明确标签，且图片可放大；不依靠猜一串装饰性数字。

登录后出现一个关联多个地点的目录，例如商场采访与地铁影像。朋友同时发来现场照片，照片里的旧编号帮助玩家检索出一份此前无法定位的记录。记录显示的情况与朋友刚发的消息矛盾，玩家回到聊天准备提醒，此时朋友发来一张更近的照片，随后通信中断。

中断后立即留有可用的调查方向，例如已收到照片中的档案编号；玩家可以继续查证发生了什么。不能用漫长空等代替后续玩法。朋友究竟遭遇什么由剧情决定，中断本身不自动证明死亡。

## 最小程序组成

| 模块 | 必要能力 |
| --- | --- |
| 网页查看 | 地址输入、页面跳转、返回、滚动、链接、图片放大 |
| 本地搜索 | 根据内容词与手写别名返回页面；支持简称、词序与常见标点差异 |
| 登录与检索 | 校验指定系统的 ID、密码或编号，成功后显示对应记录 |
| 聊天 | 按条件显示手写消息与图片；玩家通过少量回复选项或发送编号等明确输入推进 |
| 剧情与存档 | 记录已触发节点、已解锁访问、聊天位置及待显示消息 |

网站由 Unity UI 在游戏中模拟，模板填入本地数据，不需要建立真实网站、服务器、账号服务或接入真实微信。保留搜索结果、帖子／报道、登录检索、聊天四类主要模板；通过字排、色彩与少量样式变化体现网站年代和用途，不为每条怪谈制作全新界面。

数据先用简单的页面表、登录表和聊天节点表组织，具体存储格式待实现时确定；首版不建设通用剧情编辑器。

页面表：稳定页面 ID、虚拟地址、标题、正文、图片、链接、搜索词、必要的访问条件。
登录表：系统 ID、可接受账号、对应密码、成功目标、明确的失败反馈。ID 与密码必须匹配同一个账号，不能各自命中任意条目就成功。
聊天节点表：联系人、触发条件、消息顺序、文本／图片、短暂延迟、可选回复、下一节点。

## 判定方式

程序只识别少量行为：打开指定页面、登录成功、提交正确检索编号、选择回复、发出指定信息。采用简单条件与一次性剧情标记串联，不检查玩家是否收集了完整证据组合。

拿到有效账号密码可以直接登录，不要求先读过指定帖子。公开网页可以通过正确搜索词提前发现。后续对话需要兼容提前发现的记录，不让“你还没按顺序点页面”卡住进度。

搜索失败不等于剧情失败。登录与编号输入允许重试，不做永久锁号。清除粘贴产生的首尾空格；账号大小写规则、编号中的连字符与密码大小写规则按界面说明处理。关键区分要能看清，不用模糊图片制造字符歧义。

## 朋友现场叙事

朋友具有自己的调查动机，会根据剧情进展发来消息与照片；玩家可通过有限回复建议拍摄门牌、检查手边资料等。先把实际需要的分支写清楚，不承诺自由聊天。

现场图片是叙事重点资产。首版优先少量关键照片，以裁剪、局部放大和有情节意义的后续照片复用素材；不模拟实时摄影或连续行走。

风险由内容逐步建立：正常聊天 → 一处异常 → 请求确认或补拍 → 新照片与旧记录矛盾 → 消息停止。停顿的长短和最后一张图要服务具体事件，避免每次都以同一套失联方式收尾。

延迟采用游戏内调度。以玩家的调查操作和剧情节点安排遇险，不因读字慢、切出窗口或暂停而惩罚朋友。消息中断后玩家可以继续发消息，但暂时收不到回复；主线另有明确入口。

## 存档与必要验证

存档保存当前页面、搜索／浏览历史、访问权限、已触发剧情节点、聊天进度和待发送消息。朋友已经失联的状态在读档后保持，旧消息和关键图片始终可查；不能重复发出一次性消息。

需要验证：账号密码配对、两种查找顺序都可推进、提前登录不软锁、搜索简称能找到核心材料、图片可读、错误输入能重试、消息前后存读档不丢失或重复。

## 首版范围

一个搜索入口、一个论坛和报道模板、一个登录检索系统、一个联系人、少量含线索图片。做通“朋友给密码 → 搜索找到 ID → 登录查记录 → 朋友传现场照片 → 用照片编号查到矛盾 → 失联后继续调查”。网站数量与具体剧情待首段内容确定，不先扩框架。
